# Pain Point Skill

Use this checklist before shipping any feature, UI change, or experiment.
If a proposal fails this skill, revise it before implementation.

## Problem To Solve Every Time
User pain: "I save things to watch, then cannot retrieve them quickly when I actually want to watch."

## Decision Gate (Must Pass)
1. Does this reduce capture friction from social or web discovery moments?
2. Does this reduce retrieval time at "I want to watch now" moments?
3. Does this preserve saved-first results over recommendation noise?
4. Does this reduce scrolling, taps, or cognitive load versus current flow?
5. Does this end in an action (watch now, schedule, save) without dead ends?

If less than 4/5 are true, do not prioritize the feature.

## UX Guardrails
1. Do not blend saved and recommended content in one rail.
2. Do not hide saved matches below recommendation blocks.
3. Do not add mandatory form fields to share capture unless legally or technically required.
4. Do not add dashboard modules that compete with instant retrieval.
5. Do not optimize for discovery browsing at the cost of fast recall.

## UI Copy Guardrails
Use language that reinforces ownership and speed:
1. "From your list"
2. "Not in your list"
3. "Save from anywhere"
4. "Find what you already saved"

Avoid copy that implies generic browsing:
1. "Explore everything"
2. "Trending first"
3. "Discover endlessly"

## Feature Template
When proposing a feature, include:
1. User moment: capture, recall, or act
2. Time-to-value change (before vs after)
3. Saved-first impact
4. Failure case and fallback behavior
5. Success metric

## Success Metrics
1. Median time from app open to play action
2. Share-to-save completion rate
3. Search success rate from saved items
4. Sessions where user plays from saved list without external re-search
